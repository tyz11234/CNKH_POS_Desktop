## Confirmed bugs: five groups

1. **Purchase import accepts invalid quantity and saturated amounts.** `lib/services/purchase_invoice.dart:190`/`:254`/`:363`, `lib/screens/admin/purchase_create_screen.dart:504`. QR qty NaN/Infinity/1e309 reached subtotal rounding and crashed the actual draft UI; 0/-1 were silently rewritten to 1. A finite huge line total and 100-digit OCR RM value were accepted/saturated. QR factories now reject invalid/non-positive quantities, malformed/non-integral/negative/oversized cents and invalid scaled totals; OCR uses the checked money parser and throws a clear validation error. The actual paste entry catches it and retains raw text without merging a bad line. Valid zero cost, integral numeric cents, fractional quantity and normal prior imports remain covered. Baseline: `desktop/new-bugs-before.log` (first nine parser/import failures). Permanent regression: `purchase_import_validation_test.dart`.
2. **Scanner reports acceptance before asynchronous stock/add decision.** `lib/screens/barcode_scan_screen.dart:22`/`:121`/`:224`, cart binding `lib/screens/cart_screen.dart:362`. A callback returning false or pending still incremented acceptance/played feedback; thrown errors escaped. The callback now returns `Future<bool>`, both real scanner entries await it, only true adds count/feedback, and failures show an error. Purchase binding suppresses its local beep when scanner owns feedback, preserving keyboard feedback. Corrected isolated baseline: `desktop/scanner-and-purchase-dialog-before.log`. Permanent `scanner_acceptance_feedback_test.dart` counts scan feedback's selection-click channel call, so Material button click sounds cannot masquerade as acceptance.
3. **Stocktake invalid quantity gives an uncaught repository error.** `lib/screens/admin/admin_hub.dart:451`/`:474`. Actual NaN entry escaped without a snackbar. The editor validates before writing, catches repository failures visibly, preserves data, and releases its controller after route removal. Baseline: `desktop/admin-entry-before.log`; permanent `admin_entry_error_feedback_test.dart`.
4. **Receipt template write failure escapes without usable UI feedback.** `lib/widgets/receipt_template_editor.dart:133`/`:151`. A rejected settings write was unhandled. Save/reset now expose the error and release the busy state; draft values remain available. Baseline: `desktop/admin-entry-before.log` using the corrected actual Save button. Save and reset permanent failures are in `admin_entry_error_feedback_test.dart`.
5. **Focused dialog controllers are disposed during exit animation.** The controllers were freed at `Navigator.pop` completion while their TextFields still rebuilt during route exit. Actual used-after-disposed failures were recorded for focused product Save, manual purchase Join, line discount Confirm and sale-void reason; the additional customer Save, employee Cancel, PIN Cancel, purchase metadata Cancel and factory reset Cancel were independently verified as described in the extra-dialog report. Permanent regressions also cover Save/Cancel outcomes across both discount modes and editors. `lib/widgets/completed_dialog.dart` now awaits `DialogRoute.completed`; 12 relevant local-controller dialogs preserve their original builders/barrier settings and defer release until widget removal. Confirmed source entry lines: product 285; purchase create 554/737; cart 249/313; sales list 129; entities 63; users 98/219; purchase detail 111; stocktake 451; maintenance 870. Baselines: `dialog-lifecycle-before.log`, `scanner-and-purchase-dialog-before.log`, `cart-dialog-before.log`, `sale-void-dialog-before.log`, and the five independently isolated `dialog-extra-*-before.log` files.
